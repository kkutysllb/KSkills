## 当前现状分析

目前项目的技能包结构不统一：

**三种现状并存：**

| 类型 | 示例 | 特点 |
|------|------|------|
| **纯知识型** | `coding/` 全部 59 个 | 只有 SKILL.md，无代码、无依赖、无需 "安装" |
| **半成品型** | `stock/kk-business-query` | 有 SKILL.md + 脚本 + LICENSE，但无标准化安装流程 |
| **较完整型** | `common/chart-visualization` | 有 `install.sh` + 脚本 + 依赖声明，但各技能格式不统一 |

**关键差距：**
- 无统一的 **包清单文件**（`pyproject.toml` / `package.json`）
- 无统一的 **安装/卸载/更新** 流程
- 无 **依赖解析**（Python packages / system bins / env vars 混杂在 frontmatter 中，未被工具化读取）
- 无 **版本追溯**（虽然有 `version` 字段，但没有 changelog）
- 不同技能打包方式不一致（有的是 Python 脚本，有的是 Node.js，有的纯文档）

## 规划方案

### 核心原则

> 一套标准，两档 Profile，渐进式推行

**"标准技能包" = 一个自描述、可安装、可卸载、可更新的目录。**

### 方案：标准技能包结构

```
<skill-name>/
├── SKILL.md              ← 包清单（增强 frontmatter）
├── pyproject.toml         ← Python 技能的标准包描述
├── install.sh             ← 统一安装脚本
├── uninstall.sh           ← 统一卸载脚本
├── CHANGELOG.md           ← 版本变更记录
├── scripts/               ← 可执行代码
├── references/            ← 参考文档
└── tests/                 ← 测试
```

### 实施步骤

#### 阶段一：标准化 SKILL.md frontmatter（增强字段）

在已有 rich profile 基础上，新增 `package` 命名空间：

```yaml
# 新增 package 字段
package:
  type: python              # python | node | knowledge-only
  entry: scripts/cli.py     # 入口文件
  install: pip install -r requirements.txt
  uninstall: pip uninstall <name>
  compatibility:
    os: [darwin, linux, windows]
    python: ">=3.10"
```

#### 阶段二：按类型分级构建

| 技能类型 | 构建方式 | 数量 |
|----------|---------|------|
| **knowledge-only**（coding/research） | ✅ 已有足够，只需加 `package.type: knowledge-only` | 62 |
| **Python 技能**（stock/common/media） | 需要加 pyproject.toml + install.sh + 依赖声明 | ~30 |
| **Node.js 技能**（chart-visualization） | 需要 package.json + install.sh | 1 |

#### 阶段三：统一安装脚本

每个安装脚本支持标准接口：

```bash
# 安装
./install.sh                  # 自动检测 + 安装依赖
./install.sh --dry-run        # 预览要安装的内容
./install.sh --prefix ~/.local  # 指定安装路径

# 卸载
./uninstall.sh                # 清理所有安装的组件
```

#### 阶段四：版本管理

- 每个技能独立 `CHANGELOG.md`（keepachangelog 格式）
- 顶层引入 `scripts/bump-version.sh` 统一版本升级
- CI 中增加版本一致性检查

#### 阶段五：registry / 交付

- 顶层 `index.json` 或增强 README.md → 作为包的注册表
- 支持 `pip install`（对于 Python 技能）和直接 `git clone` 使用
- 可选：发布到 PyPI 或 npm

### 影响评估

| 维度 | 工作量 | 影响 |
|------|--------|------|
| 新增 package 字段到 SKILL.md | 每个 skill 约 3-5 行 YAML | 低，可批量脚本生成 |
| 为 Python 技能创建 `pyproject.toml` | ~30 个文件，每个约 15 行 | 中 |
| 编写 `install.sh` / `uninstall.sh` | ~30 套脚本 | 中 |
| 创建 `CHANGELOG.md` | 按需增量维护 | 低 |
| 顶层 registry 工具 + CI 集成 | 一次性工作 | 低 |

要进入 Coding 模式开始实施吗？建议从**阶段一**（增强 frontmatter）开始，因为对现有技能的改动最小、验证最快。
